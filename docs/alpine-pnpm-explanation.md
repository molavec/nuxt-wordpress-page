# Migrate Alpine.js from CDN to pnpm module in Nuxt

Currently, Alpine.js is loaded via a CDN link directly in the `<script>` tags of the HTML head from the `nuxt.config.ts` file. To import it as a Node.js module using `pnpm` and integrate it properly into your Nuxt project, follow these three steps:

## Step 1: Install the dependency with pnpm

First, you need to add `alpinejs` as a dependency to your project. In your terminal, run:

```bash
pnpm add alpinejs
```

## Step 2: Create a Nuxt Plugin to initialize Alpine

Since Alpine.js directly manipulates the DOM, the best practice in Nuxt is to initialize it only on the client-side to avoid hydration mismatches during Server-Side Rendering (SSR).

You should create a client-specific plugin file. You can call it `plugins/alpine.client.ts` and add the following code:

```typescript
// plugins/alpine.client.ts
import Alpine from 'alpinejs'

export default defineNuxtPlugin((nuxtApp) => {
  // Optional, but recommended for debugging and making Alpine globally accessible
  window.Alpine = Alpine
  
  // Initialize Alpine
  Alpine.start()
})
```
*Note: By including the `.client.ts` suffix, Nuxt will automatically know that this plugin should only run in the browser.*

## Step 3: Clean up `nuxt.config.ts`

Finally, you must remove the CDN script you currently have in your Nuxt configuration, since Alpine will now be included in your JavaScript bundle.

In your `nuxt.config.ts` file, remove the corresponding object inside the `app.head.script` array.

**Before:**
```typescript
script: [
  { src: 'https://cdn.jsdelivr.net/npm/alpinejs@3.x.x/dist/cdn.min.js', defer: true }
],
```

**After:**
```typescript
script: [], // You can leave it empty or remove the 'script' property entirely if you have no other scripts
```

## Step 4: Modify `scripts/build-wordpress.mjs`

This step is **CRITICAL**. According to the template rules (`wp-landing/SKILL.md`), the export process to WordPress **completely removes** the JavaScript code generated by Vue/Nuxt to keep the HTML lightweight.

If you install Alpine via `pnpm` (and configure the plugin from Step 2), Alpine will work perfectly during development (`pnpm dev`), but **it will not be included in the export to WordPress** because the `build-wordpress.mjs` script discards the `_nuxt/` folder and cleans up all `<script>` tags.

For Alpine to be included in the final output for WordPress, you must read the compiled Alpine file from `node_modules` and concatenate it into `wordpress/script.js`.

Open `scripts/build-wordpress.mjs` and modify the JS generation section (around line 284):

**Before:**
```javascript
  // 3. JS
  console.log('  ⚡ Generating JS wrapper…');
  const js = `document.addEventListener('DOMContentLoaded', function () {
  // Alpine.js handles the interactivity natively
});
`;
  writeFileSync(join(WP_DIR, 'script.js'), js, 'utf-8');
```

**After:**
```javascript
  // 3. JS
  console.log('  ⚡ Generating JS wrapper with Alpine.js…');
  
  // Read Alpine.js directly from node_modules
  const alpinePath = resolve(ROOT, 'node_modules/alpinejs/dist/cdn.min.js');
  let alpineJS = '';
  try {
    alpineJS = readFileSync(alpinePath, 'utf-8');
  } catch (err) {
    console.warn('⚠️ Alpine.js was not found in node_modules. Make sure to run pnpm install.');
  }

  const js = `
/* --- Alpine.js --- */
${alpineJS}

/* --- Custom Code --- */
document.addEventListener('DOMContentLoaded', function () {
  // Native interactivity is already handled by Alpine
});
`;
  writeFileSync(join(WP_DIR, 'script.js'), js, 'utf-8');
```

This way, the `wordpress/script.js` file will contain the Alpine.js source code without depending on the CDN, and will be ready to be enqueued in your WordPress block.

---

With these four steps, you will ensure that Alpine.js is processed locally during development and properly attached to the static JS file without relying on an external CDN.
